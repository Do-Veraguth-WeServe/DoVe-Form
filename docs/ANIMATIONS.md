# Form animation capability v1

Optional artifact field `animations:{version:1,clips:{name:node}}`; shared validation in animation-policy.mjs and contract.mjs. Existing artifacts are not rewritten. The trusted renderer prepares numeric frames and executes native Web Animations through the private iframe MessageChannel. QuickJS guests have only ui.animate(name, callback) and ui.cancelAnimation(token), no DOM or native animation objects.

Nodes: tween (numeric opacity/x/y/rotate/scaleX/scaleY), sequence, parallel, and crumple (3–8 separate surfaces converging on their common centre with independently folding transforms). Crumple needs authored panels, not a single target; this is an abstract panel-fold effect, not physical paper simulation. Bounds: 16 named clips; 16 leaves per clip; depth 4; up to 8 concurrent targets, 2 active clips, 2 seconds per tween and 8 seconds per sequence. Conflicting/duplicate targets, unsupported versions/fields/values, missing targets, undeclared clips and excessive activity fail explicitly.

Callbacks report finished/cancelled/error. Reduced motion completes asynchronously without movement. Hide/page teardown and worker failure cancel native work; no infinite iterations. Effects reset their temporary styles on completion. Persist application data only on successful completion, then redraw; keep the busy guard until persistence returns, restore recoverable UI on errors. User storage is never modified by platform acceptance fixtures.

Verification: test/animation-policy.test.mjs validates limits and backward compatibility. test/animation.test.mjs executes the actual QuickJS -> renderer -> opaque iframe pipeline, observes three distinct intermediate transforms, completion, cancellation, missing targets, reduced motion, mobile view and database-error recovery. Screenshots are isolated fixtures.

Remaining limitation: there is not yet a general automated browser acceptance gate for every arbitrary newly generated artifact. The contract validates animation structure; runtime validates target existence and execution. Passing these does not certify arbitrary visual intent. No claim that every generated animation will satisfy its visual brief.

## Isolated verification work checkpoint (2026-11-08)

Source implementation: animation-verification.mjs plus a separate trusted bundle. It opens a fresh browser context, routes only three local app-owned resources, starts the original guest in QuickJS and executes each declared clip on a copied effective DOM. No provider, authenticated session, production DB or external action is attached. Startup errors and missing/duplicate targets reject; errors in clip completion reject. Evidence binds to an artifact SHA256 and includes computed intermediate transforms/opacity, mobile viewport and synthetic intermediate/end screenshots. Dynamic DOM created during startup is captured after sanitization. Total declared execution is capped at 16 seconds with a context deadline of at most 30 seconds.

This is NOT wired into generation and NOT deployed. It is a tested prerequisite, not delivery of the requested prepublish gate. Before enabling: dedicated non-root sandboxed Chromium runtime with process-level hard termination/resource limits; bounded admission/concurrency; mandatory provider-path integration with the existing single corrective round; rejection must preserve the old artifact; persist revision-bound evidence; test actual provider/job failure and success paths; full release and live verification. Current test Chromium uses the existing test-only root harness with --no-sandbox; that must NOT be reused as a production browser service.

Scope is explicitly startup-and-declared-clips, NOT visual intent or generated interaction correctness. Generic dynamic initialization after the bounded startup snapshot, real data-dependent behavior, arbitrary click paths and persistence semantics are not certified. Isolated Post-it fixture separately checks duplicate clicks, forged window completion messages, next-card transition only after successful persistence, state surviving reload, cancellation, missing targets, reduced motion and recovery without advancing after a DB error. No user product is changed. Effects reset at completion; the next-card screenshot verifies the synthetic workflow redraw rather than permanent deformation.

Initial verifier regression exposed cancellation racing page creation; cancellation now waits for page creation before closing the page, followed by context cleanup. Retain a process watchdog requirement: a browser/context deadline alone is not a hard OS resource boundary. Test command: node build.mjs && node test/animation-verification.test.mjs; the full npm test runner now also includes animation schema, stack and verifier tests.
