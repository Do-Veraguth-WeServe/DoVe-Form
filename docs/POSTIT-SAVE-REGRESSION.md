Production frontend used elementPersistence (state/code CAS acknowledgement) while production /api/state returned only {ok:true}. The write succeeded but the client classified it as unconfirmed, froze/remounted the element and reloaded history. The affected artifact also calls crumple/pop with no animations field: there is no executable clip to run. No user artifact or state is modified by this repair.

Fix: owner-save.mjs implements an atomic owned-element CAS receipt independently of the not-yet-deployed sharing routes. It preserves grant-era protections if that history table exists, rejects stale code/state, and returns confirmed state and code revision. Production gets only that state route and helper, not the source sharing stack. Dialog close preserves chat scroll. New generated ui.animate calls lacking declarations or known literal clip names fail parseArtifact and enter the existing bounded corrective retry. Legacy stored artifacts remain loadable; an undeclared runtime clip now shows a visible explanation instead of only a callback the generated code might ignore. This static check is not universal JS analysis or visual certification.
