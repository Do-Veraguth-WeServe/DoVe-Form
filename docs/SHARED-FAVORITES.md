# Personal shared favorites — #ca705d41

Accepted shared Elements can be marked with **☆ Als Favorit speichern** under **Elemente → Geteilte Elemente**. Favorites appear alongside personal Elements in the Elements sidebar, labeled “geteilt”; opening always uses a freshly authorized shared stream, not a copied artifact. Owner and recipient preferences are independent and persist server-side across devices/reloads. Removal affects only the caller's preference. Failed saves do not optimistically claim success.

The additive element_grant_favorites table stores only authenticated user/grant pairs with cascading foreign keys. Mutations require current active grant, matching source code revision and active participants, within the existing SQLite ACL lock; auth/Origin/CSRF/body/rate limits are unchanged. Pending, revoked, unavailable and foreign grants cannot be favorited or reopened. Listing excludes unavailable favorite metadata. A new grant never inherits the previous favorite. Sidebar entries refresh on navigation/render; this is not a new metadata subscription. A stale shortcut can never restore revoked access. No generated product, state, table data, provider sharing or build approval is modified.

Tests: isolated three-account units for independent preferences, idempotency, removal, restart-equivalent reconstruction, pending/foreign/stale/revoked rejection and deletion cleanup; HTTP CSRF/Origin/type and cross-account tests; desktop/mobile browser offer/accept, favorite/sidebar opening, reload, remove/re-add, injected save failure, revocation and existing delayed Worker/DB handoff. The old installed backend fails the new test at the absent favorite method. Initial regression found accidental favorite:false on pending offers; fixed by preserving their exact old projection rather than lowering the existing test.

Migration rehearsal uses a protected disposable SQLite backup of production and compares all 22 existing table row hashes before/after constructor migration, asserts empty favorite table and integrity_check=ok, then removes the copy. No private rows or hashes are printed. Full npm test is not claimed. Source/deployed logs and screenshots are recorded separately.

Deployment gate: no active user jobs; protected code-only rollback including server.mjs, element-sharing.mjs, src/app.js, src/shared-elements.js and dist/app.js plus pm2 dump and SQLite backup. Restart only as form user. Rollback restores code at idle and restarts; leave the additive favorite table inert, never overwrite the live user database. Bridge, Worker and verifier capabilities unchanged. Release verification and commit follow only after passing gates.
