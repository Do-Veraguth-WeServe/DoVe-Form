# Element loading: public asset revalidation — #6a876098

First bounded slice, not complete resolution of Element loading/flicker.
The static route previously sent no-store for app.js, worker.js and quickjs.wasm as well as the public shell. Every fresh renderer could therefore download unchanged runtime bytes again. The regression first fails on missing content validators.

Use standard HTTP caching rather than a new library, service worker or user-data store: allowlisted public files now have SHA-256 ETags and public, no-cache. Browsers may retain bytes but MUST revalidate each use; unchanged content returns a bodyless 304, changed content returns 200 with the new hash. Hash and body are read together, not inferred from mtime/size. Atomic same-size replacements invalidate correctly. This reduces transferred bytes, not network roundtrips; no immutable/future lifetime or offline capability is claimed. The server still reads/hashes each file, avoiding stale process caches across frontend-only deployments.

All API, authentication, user content, unknown paths and missing assets remain no-store.
