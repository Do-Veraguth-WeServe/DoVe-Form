# Element connections v1

One Form-owned settings dialog (gear on configured element headers and full-screen view). It renders typed ordinary settings and requirements declared by the artifact. Connection creation, selection, tests, key rotation and revocation stay in that dialog. Artifacts store requirements only. Users own reusable private connections; copied/shared artifacts do not inherit credentials or bindings. Existing global owner-only MCP/HTTP administration is unchanged, not exposed to normal users.

Transport: public HTTPS on port 443, IPv4 with resolution validated and pinned at every request; no redirects, private/reserved IPs or arbitrary headers. Credentials currently support optional Bearer tokens, not OAuth/API-key custom headers. HTTP connections support a base URL plus user-approved relative endpoint per operation, query values and JSON body. MCP uses pinned official SDK 1.32.2 and Streamable HTTP; no stdio/local servers, server generation or process launch. Legacy owner-only transports are not used by this feature. DNS 5s, network 25s, bounded request/response sizes, at most 8 active integration/test operations and 2 guest requests per element.

Secret storage: AES-256-GCM with connection+user authenticated data; random master key in service data/connection-master.key (0600). No master key in repository. Back up that key together with form.db; losing it cannot be repaired by generating a new one. No secret value is returned by list/settings APIs, copied into artifacts or given to the model; outgoing result strings and keys redact the credential. This is service-held encryption, not end-to-end encryption against the server operator. Rotation increments revision and invalidates previous grants.

Bindings are explicit user configuration, scoped to user, message and code snapshot, including method/path/tool and effect. New/changed code requires renewed binding. HTTP non-GET always needs write effect. MCP read/write classification is a user grant, not trusted server annotations; users must classify tools accurately. Write executions require a one-use, 60-second approval bound to exact operation, arguments, user, message, code and connection revision; trusted UI shows target and arguments. No automatic replay on failure: timeout may leave the external effect unknown. Revocation blocks subsequent requests; it cannot undo an already sent external request.

Generated API: ui.settings(cb) -> {ok,values}; ui.connection(slot,operation,args,cb) -> {ok,result,error}. HTTP result {status,ok,data}; MCP result is standard tools/call payload. Only explicit buttons should call integrations; callbacks must surface missing setup/errors. Normal settings are loaded on request, not injected into persistent artifact state automatically. Saving configuration does not hot-restart the element.

Acceptance: typed schema, encrypted storage, cross-account and revision denial, single-use write approval, redaction, official SDK initialize/list/call fixture; authenticated HTTP Origin/CSRF/content-type tests; Chromium real QuickJS-to-server roundtrip with a test-only mocked outbound HTTPS boundary, masked keys, settings reload and desktop/mobile screenshots. Test preload test/connection-network-fixture.mjs is NEVER part of production startup. No live third-party account credentials used. This does not certify compatibility with every provider or OAuth flow.
